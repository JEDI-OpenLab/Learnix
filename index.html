Preuve de concept personnelle

Learnix est un assistant documentaire en ingénierie pédagogique.

Il interroge un corpus pédagogique choisi et indexé, afin de répondre à partir de documents maîtrisés plutôt qu'à partir d'une IA généraliste. L'expérience reste privée ; cette page présente la démarche, les réglages, les limites et les conditions d'un éventuel changement d'échelle.

Ingénierie pédagogique

Une démarche ADDIE pour cadrer le démonstrateur

Learnix n'est pas seulement un assemblage technique. Le projet est alimenté par une démarche d'ingénierie pédagogique : analyser le besoin, concevoir l'usage, développer le corpus, tester l'implémentation et évaluer les effets.

  1. Analyse Identifier les besoins d'accompagnement, les publics, les contraintes et les usages de l'IA déjà présents.
  2. Design Définir les scénarios, les règles de réponse, les critères de qualité et la place de Learnix dans une médiation.
  3. Développement Constituer le corpus, configurer AnythingLLM, préparer l'invite, les tests et les supports de démonstration.
  4. Implémentation Installer le démonstrateur, le connecter à l'API et à Telegram privé, puis observer les usages réels.
  5. Évaluation Tester les réponses, les refus, les limites du RAG, la lisibilité et les conditions d'un pilote plus large.

Architecture

Une chaîne RAG lisible et reproductible

L'utilisateur interroge Learnix depuis Telegram ou l'interface web. AnythingLLM retrouve des extraits du corpus, les transmet au modèle mistral-small-4-119b, puis la réponse revient à l'utilisateur via l'interface choisie.

  1. ImporterPDF, DOCX et pages web sélectionnés.
  2. IndexerExtraction, fragments, embeddings et base vectorielle.
  3. InterrogerQuestion en langage naturel depuis le web ou Telegram privé.
  4. RécupérerRecherche des fragments les plus pertinents.
  5. RépondreGénération avec consigne stricte et refus hors corpus.

Ce que veut dire RAG

RAG signifie Retrieval-Augmented Generation, ou génération augmentée par recherche documentaire. Le modèle ne répond pas seulement avec ses connaissances générales : AnythingLLM cherche d'abord les fragments pertinents dans le corpus indexé, puis transmet ces extraits au modèle pour produire une réponse cadrée.

Méthode d'installation

Une installation reproductible, sans publier le chatbot

L'installation suit une chaîne simple : choisir un outil RAG, connecter un modèle, créer un workspace documentaire, régler le comportement de réponse et brancher l'interface Telegram privée. AnythingLLM a été retenu pour cette preuve de concept, mais d'autres outils RAG existent.

Voir les étapes d'installation
  1. Choisir le socle AnythingLLM a été choisi pour créer un workspace documentaire, indexer un corpus et connecter le modèle mistral-small-4-119b via API. Des alternatives comme Dify, Open WebUI, Flowise, LangChain ou LlamaIndex pourraient être étudiées selon le contexte.
  2. Installer et sécuriser Installer AnythingLLM sur la machine ou le serveur retenu, garder l'administration privée et ne publier ni instance, ni clé, ni documents non diffusables.
  3. Connecter le modèle Renseigner la clé API disponible dans le cadre de l'accord-cadre AMUE et sélectionner mistral-small-4-119b comme modèle appelé par Learnix.
  4. Créer le workspace Créer l'espace Learnix, importer les documents, vérifier l'extraction, puis indexer le corpus dans la base vectorielle.
  5. Régler le comportement Passer le mode en Requête, fixer la température à 0, définir la phrase de refus, régler la recherche et tester les questions hors corpus.
  6. Brancher Telegram Créer le bot avec BotFather, renseigner le token dans AnythingLLM, scanner le QR code affiché pour l'appairage Telegram, puis limiter l'usage au compte personnel.

Corpus

La maîtrise documentaire est le vrai moteur de Learnix.

Le corpus doit être limité, propre, identifiable, actualisable et sans débordement. Un document copié sur le serveur ne suffit pas : il doit être importé, rattaché au workspace et indexé pour être utilisable.

Voir les principes de corpus

Inventaire minimal

  • Titre, auteur ou organisme, année.
  • Statut public, privé ou interne.
  • Licence et conditions de réutilisation.
  • Thème pédagogique principal.
  • Date d'import et qualité d'extraction.
  • Raison de l'inclusion dans Learnix.

Paramétrage

Le refus hors corpus se construit par un ensemble de réglages.

Une température basse aide, mais elle ne suffit pas. Le comportement documentaire dépend du mode de requête, du seuil de similarité, du prompt système, de la phrase de refus et des tests.

Mode Requête

Choisi parmi Agent, Chat et Requête pour privilégier la recherche documentaire.

Température 0

Variation minimale pour renforcer la fidélité au contexte transmis.

Accuracy Optimized

Ce qu'est la température

La température contrôle le niveau de variation ou de créativité du modèle. Plus elle est élevée, plus le modèle peut produire des réponses différentes, exploratoires ou imprévisibles. Dans Learnix, elle est fixée à 0 pour obtenir des réponses aussi stables que possible et réduire les extrapolations hors corpus.

Invite exacte utilisée dans AnythingLLM 
Tu es Learnix, un assistant documentaire spécialisé en ingénierie pédagogique.

Tu dois répondre exclusivement à partir du contexte documentaire fourni par AnythingLLM.

Règles obligatoires :
1. N’utilise jamais tes connaissances générales.
2. Ne réponds jamais à partir de ta mémoire interne.
3. Si aucun extrait documentaire pertinent n’est fourni dans le contexte, réponds exactement :
“Je ne trouve pas cette information dans les documents de Learnix.”
4. Si la question porte sur un sujet absent des documents, refuse de répondre avec la phrase ci-dessus.
5. Mentionne les documents utilisés uniquement si leurs extraits sont présents dans le contexte.
6. Réponds en français, de manière concise et structurée.

Important : même si tu connais la réponse, tu ne dois pas la donner si elle n’est pas présente dans les documents fournis.

Format de réponse :
- Utilise un format compatible avec Telegram.
- Privilégie le texte simple.
- Utilise des paragraphes courts.
- Utilise des listes à puces simples quand c’est utile.
- N’utilise pas de tableaux.
- N’utilise pas de titres Markdown avec #.
- N’utilise pas de listes imbriquées.
- N’utilise pas de blocs de code, sauf si l’utilisateur le demande explicitement.
- Évite le gras, l’italique et les mises en forme complexes.
- Limite les réponses à 6 puces maximum, sauf si l’utilisateur demande une réponse longue.
- Si une réponse est complexe, commence par une synthèse courte, puis propose une structuration simple.

Style :
- Réponds comme un assistant pédagogique fiable, clair et utile.
- Ne surinterprète pas les documents.
- Signale clairement les limites du contexte documentaire.
- Si plusieurs documents donnent des éléments complémentaires, distingue-les simplement.

Telegram

Pourquoi utiliser Telegram comme interface privée ?

Telegram sert d'interface légère et personnelle : Learnix reste hébergé côté AnythingLLM, la clé API ne circule pas dans Telegram, et le bot permet d'interroger rapidement le corpus depuis un téléphone ou un ordinateur. C'est utile pour une preuve de concept personnelle, pas pour un service institutionnel ouvert.

Lire la configuration Telegram

Configuration du bot

  • Créer un bot Telegram avec BotFather et récupérer le token du bot.
  • Renseigner ce token dans l'intégration Telegram d'AnythingLLM.
  • Scanner le QR code affiché par AnythingLLM pour l'appairage Telegram.
  • Associer le bot au workspace Learnix.
  • Activer la restriction d'usage et autoriser uniquement le compte personnel.
  • Désactiver l'usage en groupes et éviter tout droit d'administration.

Limites des IA grand public

Pourquoi ne pas se contenter d'un GPT, d'un Gem ou d'un assistant généraliste dédié ?

Un assistant grand public, même personnalisé, reste souvent trop ouvert : il peut mobiliser ses connaissances générales, produire une réponse plausible sans source claire, mélanger des éléments hors corpus et donner une impression de maîtrise documentaire qu'on ne contrôle pas entièrement.

Ce que Learnix cherche à éviter

  • Réponses plausibles mais non documentées.
  • Débordement hors corpus pédagogique.
  • Sources absentes, floues ou reconstituées.
  • Dépendance à une mémoire ou à des connaissances générales non vérifiables.
  • Confusion entre outil de médiation et autorité pédagogique.
  • Perte de maîtrise sur les documents réellement utilisés.

Passage à l'échelle

Du démonstrateur personnel au pilote accompagné

Learnix peut servir de preuve d'usage. L'étape raisonnable n'est pas une ouverture large immédiate, mais un pilote interne avec une équipe restreinte, un corpus gouverné et une évaluation explicite.

  1. Phase 0Démonstrateur personnel privé.
  2. Phase 1Pilote interne au centre d'innovation pédagogique.
  3. Phase 2Bêta avec enseignants volontaires et accompagnés.
  4. Phase 3Service institutionnel, si la gouvernance suit.

Impact et changement d'échelle

De l'API AMUE au modèle local : une question technique, écologique et institutionnelle

Le démonstrateur utilise aujourd'hui une API mise à disposition dans le cadre de l'accord-cadre avec l'AMUE. C'est adapté pour prouver l'usage rapidement, mais ce n'est pas une solution que l'on peut qualifier de sobre par principe. Si Learnix devait changer d'échelle, il faudrait discuter l'empreinte, la dépendance à un service distant et la possibilité d'une infrastructure locale ou institutionnelle maîtrisée.

Point de vigilance

Viser un LLM local ne veut pas forcément dire réentraîner entièrement un modèle. Dans une approche RAG, le modèle peut rester général tandis que le corpus est local, indexé et strictement maîtrisé. Un fine-tuning ou un entraînement spécifique serait un autre changement d'échelle, plus coûteux, à évaluer sur les plans technique, écologique et pédagogique.

Vigilance

Ce qui conditionne toute ouverture collective

Pas de données étudiantes nominatives, de copies, de données RH ou sensibles dans le démonstrateur personnel.

Une clé API personnelle ne doit pas devenir l'infrastructure d'un service collectif.

Un passage à l'échelle suppose authentification, droits, charte d'usage, support, maintenance et cadrage RGPD.

Repères

Les points clés du démonstrateur

Ces repères rassemblent les choix pédagogiques, techniques et méthodologiques qui permettent de comprendre Learnix sans accéder au chatbot privé.

Démarche et ADDIE

Learnix est pensé comme un objet d'ingénierie pédagogique, pas comme un simple assemblage technique. La démarche ADDIE structure l'expérimentation.

  • Analyse : identifier besoins, publics, contraintes et documents disponibles.
  • Design : définir scénarios, règles de réponse et critères d'acceptabilité.
  • Développement : constituer le corpus, configurer AnythingLLM et préparer l'invite.
  • Implémentation : tester l'interface web, Telegram privé et les usages réels.
  • Évaluation : vérifier réponses, refus, lisibilité et risques de surinterprétation.
Architecture et RAG

RAG signifie Retrieval-Augmented Generation : AnythingLLM cherche d'abord des extraits dans la base documentaire, puis transmet ce contexte au modèle pour produire une réponse cadrée.

  • L'utilisateur pose une question depuis Telegram privé ou l'interface web.
  • AnythingLLM interroge le workspace Learnix.
  • La base vectorielle retrouve les fragments proches de la question.
  • Le modèle mistral-small-4-119b formule une réponse à partir des extraits récupérés.
  • La réponse revient via l'interface utilisée, sans ouverture publique du chatbot.

  • Installer AnythingLLM et créer un workspace Learnix réservé au démonstrateur.

  • Importer une base documentaire propre, vérifier l'extraction puis indexer les documents.

Principes de corpus

Le corpus est le cœur de Learnix. Sans documents propres, identifiés et réellement indexés, l'assistant documentaire perd son intérêt.

  • Limiter le corpus dans un premier temps.
  • Choisir des sources cohérentes avec les usages pédagogiques visés.
  • Documenter titre, auteur, année, statut, licence, thème et raison d'inclusion.
  • Noter la qualité d'extraction et la date d'import dans AnythingLLM.
  • Ne pas publier de documents internes, de données personnelles ou de ressources sous droits sans vérification.
  • Importer, rattacher au workspace puis indexer : copier un fichier dans un dossier ne suffit pas.
Paramétrage AnythingLLM

Le refus hors corpus repose sur un ensemble de réglages, pas sur la seule température.

  • Mode de chat : Requête.

Vigilance et IA grand public

Un GPT, un Gem ou un assistant grand public dédié peut rester trop ouvert pour ce besoin : il risque de mobiliser des connaissances générales et de produire une réponse plausible sans source maîtrisée.

  • Éviter les réponses plausibles mais non documentées.
  • Limiter le débordement hors corpus pédagogique.
  • Ne pas confondre assistant de médiation et autorité pédagogique.
  • Ne pas traiter de données étudiantes, RH, sensibles ou confidentielles.
  • Prévoir gouvernance, droits, support, maintenance et cadrage RGPD avant toute ouverture.
Tests de comportement

Les tests servent à vérifier que Learnix reste un assistant documentaire, pas un chatbot généraliste.

  • Question hors corpus : vérifier le refus exact.
  • Question simple : vérifier l'appui sur les documents indexés.
  • Question complexe : observer la structuration et les limites explicites.
  • Document long : repérer les synthèses partielles liées à la récupération RAG.
  • Telegram : vérifier longueur, lisibilité mobile et absence de mise en forme complexe.
  • Ajuster le corpus, le seuil ou le prompt si le comportement dérive.
Trajectoire et impact

Le démonstrateur utilise une API mise à disposition dans le cadre de l'accord-cadre avec l'AMUE. C'est utile pour prouver l'usage, mais le passage à l'échelle demanderait une réflexion technique, écologique et institutionnelle.

  • Phase 0 : démonstrateur personnel privé.
  • Phase 1 : pilote interne avec une équipe restreinte.
  • Phase 2 : bêta accompagnée avec enseignants volontaires.
  • Phase 3 : service institutionnel uniquement si la gouvernance suit.
  • Un LLM local peut être envisagé avec un corpus local indexé, sans forcément réentraîner un modèle.
Chantier Moodle vers Learnix : suivi et playbook technique

Un chantier en cours étudie comment faire de Moodle une source documentaire pour Learnix. On n'importe pas la base Moodle : on extrait un corpus pédagogique filtré, structuré et validé via les web services, puis on l'importe dans AnythingLLM. Statut : conception terminée, réalisation à venir (Phase 0 bis).

  • Extraction par les web services REST de Moodle, jamais par lecture directe de la base SQL.
  • Compte technique dédié et token révocable, limité aux seules fonctions de contenu.
  • Types pleinement extractibles : Pages, Étiquettes et ressources Fichier. À éviter pour le contenu essentiel : Livres, Dossiers, Glossaires et Wikis, mal exposés par l'API.
  • Sortie en Markdown lisible, avec un manifeste et le chemin de catégories pour préserver le contexte pédagogique.
  • Validation humaine obligatoire et exclusion par défaut des notes, rendus, comptes et traces : aucune donnée personnelle dans Learnix.
  • Feuille de route en six étapes, du cours test à la recette, avec un livrable vérifiable à chaque étape.

Le suivi détaillé et le playbook technique pas à pas sont tenus à jour dans la documentation du dépôt (docs/avancement-moodle.md et docs/extraction-technique-moodle.md).
